# 004: CLI skeleton and shared flags

Status: Accepted
Prefix: CL

## Goal

The behaviour every molt command shares, built once, before any real command: global flags, exit codes, reading the environment into the context that safe delete and the rules engine are given, loading config and rules so that a bad file stops molt up front, and refusing to run as root.

## Non-goals

- Any real command (`scan` is 005, #4). With no command, molt prints its help, as now.
- The system step that may run as root. That is 007 (#7).
- Interactive confirmation. `--yes` is accepted here; `clean` (006) acts on it.

## Model

Startup runs these steps in order. Any failure stops molt before the command runs:

1. Parse the arguments (CL-01, CL-02).
2. Refuse root (CL-07).
3. Read the environment into the context (CL-04, CL-05).
4. Load the config and the rules, and drop disabled rules (003, 002).
5. Decide live or dry run (CF-07), and say why if it's a dry run (CL-06).

## Requirements

### Flags
- **CL-01** `--dry-run`, `--live`, `--yes` and `--json` are global: they're accepted before or after the command name.
- **CL-02** `--dry-run` with `--live` is a usage error (exit 2), as is any unknown flag or command.

### Exit codes
- **CL-03** molt exits 0 on success, 1 on a fatal error with nothing changed, 2 on bad usage, and 3 on partial success (P-13). A fatal error prints one line to stderr naming what went wrong, starting with `molt: `.

### Environment
- **CL-04** `$HOME` must be set, absolute and valid UTF-8, or molt stops (exit 1). Each `$XDG_*_HOME` is used only when it's absolute; otherwise its XDG default applies (`~/.config`, `~/.cache`, `~/.local/share`, `~/.local/state`), as the XDG Base Directory spec says.
- **CL-05** The operation log lives at `$XDG_STATE_HOME/molt/operations.log`. `MOLT_NO_OPLOG=1` turns it off. Any value other than `0` or `1` is an error (exit 1), as for `MOLT_DRY_RUN` (CF-07).
- **CL-06** When the config or `MOLT_DRY_RUN` makes a run a dry run, molt says so on stderr, names which one, and says that `--live` acts.

### Root
- **CL-07** If the effective uid is 0, molt refuses to run (exit 1) and says to run it as the normal user. `--help` and `--version` still work. Until the system step (007) exists, there is no way around this.

### Failing closed
- **CL-08** A config or rule file that exists but can't be read or parsed, an unknown disabled rule, or a bad `MOLT_DRY_RUN` value stops molt with exit 1 before the command runs (P-03).

### JSON
- **CL-09** With `--json`, a fatal error is also written to stdout as one JSON object, `{"error": "<message>"}`, so scripts can parse it. The exit code is unchanged.

## Test strategy

- Smoke tests run the real binary with the environment cleared, `HOME` and every `XDG_*` variable pointed into a temp dir, and `PATH` empty. No smoke test may see the real home directory.
- Environment parsing (CL-04, CL-05) is a pure function over the variables, tested with a table.
- CL-07 is tested by injecting the uid into that function. The real binary can't be started as root in CI.
- P-05: the startup steps write nothing. A smoke test snapshots the temp home before and after a run.

## Decisions

- **No `--debug` yet.** It arrives with the first command that has something to debug.
- **JSON errors on stdout too** (CL-09).
- **Root is refused for every command**, read-only ones included (CL-07, P-04). A scan as root reads root's home, so its results would mislead.
